# C2 Lite as a Pro Controller 2 (Switch 2, Bluetooth LE)

From stage 11 on, with the slider on **Switch**, the C2 Lite presents itself as a genuine **Pro Controller 2** over
Bluetooth LE. Pairing, playing, reconnecting and **waking the Switch 2 from standby with the controller's own address**
work, without a borrowed Joy-Con identity and without any setup. Confirmed on hardware on 2026-10-30 with a Switch 2
(console firmware of October 2026).

German version (more detail on the process): [`PRO-CONTROLLER-2.md`](PRO-CONTROLLER-2.md). Code: `modules/c2lite/c2_pro2.c`
in the SDK patch (`sdk-arbeit/sdk-aenderungen.patch`), GATT table generated by `werkzeuge/pro2_profil.py`.

## Usage

| Step | What to do |
|---|---|
| Pair (once) | Slider on **Switch**, Switch 2 on, open Controllers → "Change Grip/Order". The C2 Lite advertises as a Pro Controller 2 and the console pairs it (rumble, player LED). |
| Play | Slider on Switch, power on: reconnects by itself (encrypted with the stored key). |
| Wake the Switch | Press **Home** (or power the controller on): 10 s wake advertisement with its own address. |
| Standby | When the console sleeps, the controller keeps looking for 30 s and then powers off (on a charger: charge sleep). |
| Wired to the Switch | stays the classic wired Pro Controller; Bluetooth is silent meanwhile. |
| Old way | `c2lite-custom roh pro2 klassisch`: Switch 1 Pro Controller over Bluetooth Classic, wake with a borrowed Joy-Con identity. Back with `pro2 standard`. |

Commands (USB serial with the slider on PC, or `c2lite-custom roh …`): `pro2 status`, `pro2 standard|klassisch`,
`pro2 vergessen` (forget pairing), `pro2 spur` (event trace), `pro2 trennen` (disconnect), `pro2 an|einmal|aus`
(development: Pro Controller 2 also with the slider on PC, USB log stays available), `pro2 debug an|aus`.

Limits: two eccentric rotating mass motors cannot do HD rumble; only the amplitude per side is used, vibration
patterns (connect, "Search for controllers") become strong pulses. No motion sensor (zeros), no NFC, no headset jack.
Wired it remains the Switch 1 Pro Controller (the Pro Controller 2 USB mode is not emulated).

## What we learned (ground truth)

Sources: [ndeadly/switch2_controller_research](https://github.com/ndeadly/switch2_controller_research) (protocol and
decrypted air captures, facts only, no license), working ESP32 emulators
[2017fighting/ESP32-BLE5-NSController-Emulator](https://github.com/2017fighting/ESP32-BLE5-NSController-Emulator) (MIT),
[virgil724/playgate-switch2-gateway](https://github.com/virgil724/playgate-switch2-gateway),
[espp PR #765](https://github.com/esp-cpp/espp/pull/765), SDL `SDL_hidapi_switch2.c` (`EncodeHDRumble`, zlib).
Jieli's `btctrler.a` and `btstack.a` are **LLVM bitcode with debug info**; `llvm-dis-18` turns them into readable IR.

Pitfalls found on hardware:

1. **ATT MTU 512.** If the controller answers `MTU_REQ 512` with less (we had 247), the Switch sends **nothing**
   afterwards: no discovery, no commands, the link just idles. With 512 like the real controller, pairing completes.
2. **DLE and 2M PHY.** Without long data packets and 2M (Jieli `CONFIG_BLE_HIGH_SPEED 0`) the console stalls right
   after `LL_FEATURE_REQ`.
3. **5 ms connection interval** (below the 7.5 ms spec minimum): NimBLE needs a patch; Jieli's `ll_slave.c` accepts it
   unchecked. The C2 Lite reconnects at 5 ms directly.
4. **No SMP.** Pairing runs over command 0x15 (`LTK = A1 ^ B1`, `B2 = AES-128(rev LTK, rev A2)`, B1 fixed
   `5CF6EE792CDF05E1BA2B6325C41A5F10`, verified by `werkzeuge/test_pro2_krypto.c`); then LL encryption with EDIV = 0,
   Rand = 0.
5. **Do not queue reports** (lag): send only when the TX buffer is empty.
6. **Vibration patterns**: "Search for controllers" sends pattern 2 and 150 ms later pattern 0; ERM motors need a
   longer, full-strength pulse to be felt.
7. **Do not advertise forever after standby**: power off after 30 s like the original.

Jieli specifics:

- **Injecting the LTK:** `sm.c` answers an LTK request with EDIV = 0 / Rand = 0 and no own entry through the weak hook
  `u8 sm_info_null_set_ltk_reply(u16 conn_handle, u8 *ltk)`; return 1 and the stack reverses the buffer and calls
  `ll_hci_long_term_key_request_reply`, so store the LTK **reversed**. `le_device_db_add` is a stub (returns -1).
- **Fixed handles:** the GATT table is a byte array in the format of Jieli's `gatt_inc_generator`; handles follow the
  order. `werkzeuge/pro2_profil.py` generates it and checks every handle against the documentation.
- **Own GATT control block** instead of BLE HID (`ble_comm_init`, `ble_gatt_server_set_profile`, `adv_cfg_t` with
  `USE_SET_LOCAL_ADDRESS_TAG`), Bluetooth Classic off.
- **Debugging:** `pro2 spur` (RAM event trace incl. every incoming ATT PDU, hooked in front of the library's ATT server
  via `att_global_info` field 1),
  `C2_BLE_DIAGNOSE` (link layer control PDUs, ATT/SM messages). Use only one program on the USB serial port.
